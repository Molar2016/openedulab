# OpenEduLab 需求对齐稿 v2（已由 requirements-v2.1.md 取代）

> 本文件仅作历史草稿，不作为开发依据；以 `docs/requirements-v2.1.md` 为准。

日期：2026-10-26。优先级：用户在飞书中的后续口头澄清 > 章程 v1 的冲突条款。本文只定义产品行为，不决定技术栈或部署。

## 已明确
1. 网页平台，教师主要用于课堂展示和解释实验；学生也可自行使用。无需区分教师、学生角色；不做教师给学生布置作业的流程。
2. 所有人可自行注册。打开实验资源前必须登录；首版以手机号或邮箱作为账号标识，使用密码登录，不做号码/邮箱归属验证。该标识只用于区分站内账户，不能宣称已核实真实身份。
3. 登录者能收藏实验/资源，并查看自己的使用历史；不应看到平台内部的诊断报告或其他账户记录。
4. 平台后端关联账号收集最少必要的使用事件与错误/问题报告，用于判断资源使用和改进产品；这些内部报告不在个人页面展示。个人收藏/历史与内部分析报告属于两类用途不同的数据。
5. 初期免费；未来可能开源并在平台维护成本方面收费，但首版不做付费系统。
6. 先做能跑通完整路径的基础平台与少量真实内容，不批量制作实验。首款函数图像实验是章程的建议样例，尚待确认优先级。
7. 部署、域名、公开上线、扩大数据采集须单独确认；不得影响既有线上服务。

## 章程 v1 被覆盖之处
- “无需登录”“账户 P2 延期”已撤回：登录/注册是首版必要功能。
- “只统计匿名汇总事件”已撤回：内部事件必须能关联站内账户，但不等于验证真实身份。公开输出仍不能暴露个人记录。
- “纯静态站点即可”的设想不再是前提：账户、收藏、历史和后端报告需要持久服务端能力。具体架构待需求确认后设计。

## 建议首版验收路径（供确认）
访客打开首页 → 注册/登录 → 找到实验 → 调整参数/全屏/重置 → 收藏 → 在“我的收藏/最近使用”中再次打开 → 平台私有端可查到按账户关联的实验打开/交互/错误摘要，普通账户看不到他人或后台报告。注销后资源页要求重新登录。失败路径至少含重复标识注册、错误密码、未登录直达资源 URL、会话过期。邮箱/手机号不验证时不提供不安全的自助密码找回。

## 待确认的产品边界
- “行为历史”首版是否仅展示最近打开过的实验及时间（建议），还是展示每次参数操作的明细？建议后者不做。
- 首版是否需要“我的收藏”和“最近使用”都上线，还是先收藏、历史延期？按当前表达暂视为两者都做。
- 首款内容是否继续用一次函数/二次函数联动实验？若用户有更贴近授课的题目，以用户指定为准。

## 暂不设计
账号角色/班级/作业/成绩、验证码/第三方登录、收费、实验编辑器、大规模内容库；服务器选型、数据库、插件协议及部署拓扑留待需求确认后评审。
