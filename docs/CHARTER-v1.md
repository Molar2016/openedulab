# OpenEduLab（暂定名）——开源互动教学平台项目章程与 AI 执行规范 v1.0

> 状态：可执行规划稿（名称、域名、服务器参数待确认）。日期：2026-10-26。
> 面向：AI 开发代理、项目维护者、未来开源贡献者。
> 目标：打造无需登录、打开网页即可使用、可离线、低配置友好、多语言的公益互动教学工具；将各实验作为独立插件长期扩展。本文要求优先于 AI 的个人技术偏好。

## 0. 立即执行的总指令

本项目先建立可持续扩展、可测试、可观察的最小稳定底座，再做少量真实实验。不要一次性实现所有学科、收费系统、用户账户、教师后台、AI 生成实验编辑器。**严禁为追求演示效果而伪造科学结果，严禁在未获授权情况下复制第三方实验资源。**

执行时：先侦察仓库、机器、域名、端口、既有部署；不得破坏或覆盖现有服务；形成执行计划与验收清单；完成一个里程碑后运行测试、提交版本并留存证据。部署生产环境、修改防火墙或 DNS、开通收费、启用额外收集用户数据等外部变更应取得项目所有者明确批准。

## 1. 愿景与优先级

- 公益优先：公共核心实验永久免费使用；网页访问无登录门槛。
- 教师优先：3 秒内能找到开始入口（主观可用性目标，非网络 SLA）；全屏投影、重置、暂停、预测再验证方便。
- 科学可靠：实验模型标明假设、适用边界、公式依据；模型测试与渲染测试分离。
- 可持续：浏览器侧运算优先，服务器主要分发静态文件；低配置与离线能力。
- 国际化：第一阶段 `zh-CN`、`en`，语言与课程映射解耦。
- 可复用：公共设计系统与稳定实验 SDK；新增实验无需修改底座核心。
- 开源透明：代码、建设过程、问题及发布记录公开；用户行为数据只发布汇总，不公开个人会话。
- 内容共创：开发时自动积累短视频素材，保留可验证的开发里程碑、截图、录屏、实验故事。

## 2. 用户与场景

1. 教师在教室电脑/投影/触控屏访问网站，搜索实验，一键全屏，调整参数，展示规律。
2. 家长在手机/电脑打开链接与孩子操作，不需安装 APP。
3. 网络不佳学校预先缓存或下载实验包，脱网使用核心实验。
4. 开源贡献者按实验接口新增插件，无需理解网站部署、埋点、国际化的全部细节。
5. 维护者从匿名汇总事件、错误日志、人工反馈判断修复与选题优先级。

## 3. 范围控制

### P0：必须实现

- 首页、学科/学段/知识点检索、实验详情/运行页、全屏模式、重置与标准控制。
- 两种语言和可扩展翻译格式；实验 manifest 元数据与自动生成路由/目录。
- 插件式实验运行容器；错误隔离；共享组件；版本与兼容性检查。
- 一个低复杂度的真实教学实验作为端到端验证：**一次函数与二次函数参数联动**（或分数可视化）。
- 基础访问分析与**有限、透明、匿名的产品事件**：进入、开始交互、重置、全屏、完成等。
- 客户端异常监控：错误类型、版本、实验 ID、浏览器大类和最少必要的技术诊断数据；敏感信息过滤和限流。
- 可选“反馈问题”按钮，提交前给用户查看提交内容；无需登录。
- 自动测试、演示截图、简短录屏和版本说明；CI 检查与回滚方案。
- HTTPS、移动端响应式布局、基础可访问性、隐私声明、开源仓库 README 与贡献规则。

### P1：公共版本完善

- 增加 5 个正式实验，形成约 6 个高质量实验的可公开版本。
- PWA 离线缓存，含更新机制和离线可用性验证；必要时提供便携离线包。
- 内容准确性评审表、自动采样测试、老师可理解的实验说明。
- 轻量内部管理视图：高频实验、互动使用率、错误趋势、版本对比、反馈工单。
- 社交分享卡片、短视频素材索引、屏幕录制工具脚本。

### P2：明确延期

- 注册登录、学生账户、作业系统、教学成绩收集、教师社区、支付、完整课程管理系统。
- 复杂电路搭建、三维实验编辑器、自动生成数百实验、用户上传可执行脚本。
- 全站会话录像、鼠标轨迹追踪、跨站识别、用户画像。

## 4. 不易变更的分层架构

```text
Browser / PWA
  App Shell: 导航、搜索、路由、多语言、分享、全屏、主题、访问性
    Experiment Host: 容器、生命周期、控制台、错误边界、观测适配器
      Experiment SDK: 稳定类型契约、参数与结果约定、复用控件
        Experiment Modules: 每个实验独立 models / views / tests / translations / manifest
  Analytics Adapter (可替换)
  Feedback Adapter (可替换)
  Error Reporter (可替换)
Static hosting/CDN: 站点文件、插图、翻译包、实验模块
Optional backend: 反馈接收、错误聚合、限流、汇总仪表板
Optional external/self-hosted analytics: Umami
```

**禁止**实验模块直接操作全局导航 DOM、直接调用第三方统计 SDK、直接读取服务器数据库、在模块中改写路由、直接访问其他实验的内部文件。通过稳定接口调用主程序服务。禁用隐式全局可变状态。

## 5. 推荐技术栈与工程决策

- 前端：React + TypeScript + Vite；初期不需要 SSR。按需加载实验代码。
- 数学可视化：SVG/Canvas；二维运动时按需求使用成熟物理库；Three.js 只用于必须 3D 的实验。
- i18n：i18next；翻译键稳定，默认回退中文或英文并报告缺失。
- PWA：Workbox 或成熟 Vite PWA 方案；P1 实现，避免误缓存错误版本。
- 单仓库包结构：pnpm workspaces（项目足够小时不引入重型 monorepo 框架）。
- 测试：Vitest + React Testing Library + Playwright；类型检查、lint、构建、关键功能截图校验。
- 部署：优先已有服务器上的 Docker 或静态反向代理，但以环境侦察结果为准；HTTPS；发布为不可变版本目录，支持快速切回。
- 分析：Umami（可自建），接入 AnalyticsAdapter；如果服务器资源不足，先使用轻量服务或合法合规的托管方案，不绑死于供应商。
- 异常：前端捕获可控错误 + 全局异常，统一上传到私有错误接收端；最初也可采用具备隐私过滤的成熟监控系统。
- 免费、开源并不等于第三方素材都可商用。逐项建 `THIRD_PARTY_LICENSES.md`；自创代码的许可需单独决策（MIT / Apache-2.0），图片、内容和翻译许可分开选择。

## 6. 插件协议（由 AI 提案，开发时验证后锁定 v1）

初始草案：

```ts
export interface ExperimentManifest {
  id: string;                    // 稳定，例如 math.quadratic-graph
  slug: string;                  // 稳定的公开 URL 组成部分
  moduleVersion: string;         // semver
  sdkVersionRange: string;       // 主机可校验兼容版本
  titleKey: string;
  descriptionKey: string;
  subjects: string[];
  grades: string[];               // 学段标签，不硬编码教材章节
  concepts: string[];
  languages: string[];
  offlineSupport: boolean;
  reviewedStatus: 'draft' | 'verified';
}
export interface ExperimentContext {
  locale: string;
  analytics: {
    track(event: ExperimentEvent): void;
  };
  ui: {
    requestFullscreen(): Promise<void>;
  };
}
export interface ExperimentModule {
  manifest: ExperimentManifest;
  mount(element: HTMLElement, ctx: ExperimentContext): () => void;
}
export type ExperimentEvent = {
  type: 'experiment_start' | 'parameter_changed' | 'reset' | 'fullscreen_enter' | 'experiment_complete';
  experimentId: string;
  parameterGroup?: string; // 白名单枚举，禁止自由文本与敏感值
};
```

要求：该草案不能机械套用。应评估 React 生命周期与 host 设计，并在 `docs/architecture/ADR-001-experiment-contract.md` 决定最终协议、参数状态恢复、暂停/重置、翻译键、渲染异常与卸载清理。优先消除不必要的重复抽象。每个 SDK 破坏性变化需升级主版本；旧实验可在兼容层运行。**不要一开始承诺永久不改底座**；实现可控演进与兼容测试，才是现实目标。

## 8. 数据与隐私：既能发现真实问题，也不监视学生

用户无需注册。默认只统计必要的聚合访问量与白名单化互动事件。建议事件：

| event | 用途 | 属性白名单 |
|---|---|---|
| experiment_open | 哪些实验受欢迎 | experiment_id, module_version, locale |
| experiment_interact | 是否真正动手 | experiment_id, control_group, interaction_bucket |
| experiment_reset | 复位频率 | experiment_id |
| experiment_fullscreen | 课堂场景代理信号 | experiment_id, enter_or_exit |
| experiment_error | 哪些实验出错 | experiment_id, error_code, app_version |
| feedback_submitted | 收到反馈 | experiment_id, issue_category |

- 滑块连续拖动必须**采样/节流/分桶**；不要上传逐帧坐标、完整输入文本、姓名、电话、学生身份、具体课堂内容、持久设备指纹。
- 禁止默认启用会话录制、键盘录入、鼠标路径、屏幕截图；后期如确有需要，单独隐私评估、明确告知并采用合理的选择机制。
- 实验运行数据默认保留在浏览器。若需要提交问题，先向用户展示上报内容，允许删减。
- 错误堆栈应清洗 URL 查询串、令牌、可能的个人文本；生产 sourcemap 私有保存。
- 访客和会话统计是估算，不能把访问量等同于真实教师或学生人数；全屏也不等于一定在课堂中使用。
- 分析/监控/反馈服务均可禁用。若因网络或隐私选择关闭，不影响实验运行。
- 编写隐私声明、数据字典、保留期限、删除策略与服务地域说明；上线前按服务地区及未成年人保护要求核查合规。

### 第一版内部管理面板

仅管理员访问，不能暴露原始反馈与异常详情到公共网页。显示：访问趋势、打开实验排行、开始交互比例、异常率、全屏比例、移动端适配问题、版本回归、反馈类型排行、待修复问题列表。数据缺失时显示“未知”，不得补造。

### 数据驱动诊断规则

- `experiment_open` 大量增加但 `experiment_interact` 很少：检查首屏说明、操作入口、设备兼容问题。
- 同一实验某版本 `experiment_error` 突增：优先回滚或停止发布。
- 进入实验后立即退出：只提示“可能存在体验问题”，不能推断用户真实意图。
- 高频重置：可能是老师重复演示，也可能是操作不清楚，需要更多证据。

## 9. 视频内容的自动留存机制

每个实验开发时维护 `content/social/<experiment-id>/`，保留：

1. 一句话教学问题与短视频钩子（例：“为什么同一个凸透镜，物体前后移动，像会翻转？”）。
2. 第一版可运行画面（10–20 秒，建议清晰录屏）。
3. 参数交互的关键片段（10–30 秒）。
4. 一个真实的开发难点与前后修复对照；只记录实际发生的问题，不编造“AI 翻车”。
5. 竖屏 9:16 和教学横屏 16:9 录制清单，必要时另存 3:4 封面截图；统一标题、字幕和水印安全区。
6. 实验公开 URL、Git commit、版本号、素材许可、录制日期与是否可公开。
7. 视频脚本模板：前 3 秒问题 → 实验操作 → 看到什么规律 → 免费使用入口 → 开源参与方式。

自动脚本：Playwright 在固定视口与固定随机种子（若适用）下产生关键截图；短录屏先用 Playwright/FFmpeg 或人工录屏实现。脚本失败不得阻碍修复教学准确性。**开发归档与公开视频素材分开存放**：内部日志、凭据、访客信息、服务器 IP 不得进入视频。

发布里程碑建议：①项目缘起；②底座首次可运行；③第一款实验；④一个真实 Bug 修复；⑤公开上线；⑥基于匿名汇总数据的迭代。视频不是只做开发日志，而是每条都有一个可学到的科学知识或操作技巧。

## 10. 发布与持续验证

CI 必须包含：类型检查、lint、单元测试、构建、实验 manifest schema 验证、翻译键完整性、必要 E2E 测试、基础无障碍检查。新插件必须通过统一契约测试。

- 科学模型测试：常规值、临界值、非法输入、单位一致性、舍入误差。
- 生命周期测试：多次打开/关闭插件无残留计时器、监听器和资源泄露。
- 兼容测试：新 SDK 不得无意破坏已验证实验；保留各实验黄金用例。
- UI 测试：手机屏幕、低分辨率投影、16:9 桌面、全屏与退出、语言切换、离线行为。
- 隐私测试：未经同意的情况下不发送敏感字段；关闭分析不会影响实验；反馈内容必须先预览。
- 部署测试：健康检查、静态资源缓存、版本显示、错误回滚；不得覆盖现有服务器应用。
- 生产验证：URL 可用、HTTPS 正常、普通访客无需账户、监控仅有演示测试事件、公开文案准确。

**每次发布必须留存可见证据**：自动测试报告、页面截图、短录屏、Git 提交号、部署版本与链接。`projectStatus.md` 更新当前状态、下一步、阻塞与恢复命令，保证 Agent 中断可接续。

## 11. 执行路线与里程碑

### M0：只读环境侦察与技术决策

检查代码仓库是否存在、服务器 OS/资源、现有应用、反代、域名、容器运行方式、备份、SSL、存储与可用端口。写 `docs/architecture/ADR-000-foundation.md`，说明技术取舍；提出不会影响现有系统的部署方式。未知项记录为待确认，不猜测。**不得未经同意直接改线上服务。**

验收：风险清单、架构图、模块协议草案、目录树、部署计划、初期验收标准。

### M1：稳定底座与可运行样例

实现网站框架、路由、搜索目录、双语、实验容器、全屏和重置、可替换监控接口、错误边界；完成数学曲线实验。自动部署到测试环境，出截图、录屏。

验收：只更改实验目录/manifest 就能注册新实验；第一款实验在 PC 与手机可操作；禁用统计也能运行；CI 绿色。

### M2：可观察且可公开的初始版本

接入 Umami（或轻量等效实现）、错误上报、反馈入口、隐私说明、内控面板、HTTPS；增加至少一款**不同学科**的实验，验证宿主不是为了数学特化。公开访问前先完成必要备案/许可和安全检查。

验收：可从匿名汇总数据看出实验被打开与发生交互；错误能关联版本；反馈可查看；新增不同学科实验无需改动宿主核心。

### M3：第一批 6 个正式实验 + 离线

补全约 6 个高质量实验；独立审查数学/科学模型；PWA 离线及更新；形成教师教学指引；测试已有实验不被破坏。

验收：6 个实验的知识点与假设清楚、测试齐备、不同尺寸稳定、能用一个版本号回滚、关键页面有可复用视频素材。

### M4：社区与迭代

GitHub issues 模板、贡献指南、版本路线图、公开 bug 列表；根据匿名数据和实际反馈决定优先级。收费托管和机构定制待用户需求真实出现后再设计。

## 12. AI 执行权限与行为规则

1. 第一次执行必须先读本文和 `projectStatus.md`；列出 5–10 项任务并明确依赖。
2. **不要在每一步反复问项目所有者**；技术细节自行判断、留 ADR，但服务器生产改动、费用、安全配置、公开上线及隐私扩大采集等风险操作必须申请批准。
3. 先复用质量可控且许可兼容的库，不轻易引入重型后端、收费 SaaS 或大量依赖。
4. 不允许用没有物理依据的动画蒙混过关；模型公式、假设、已知局限必须可核查。
5. 修改底座必须解释原因，记录 ADR，并运行所有既有实验的回归测试；破坏性接口变更须有迁移计划。
6. 每个功能要有可观察验收：构建成功不算完成，必须有测试和截图/录屏/URL 证据。
