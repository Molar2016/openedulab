# OpenEduLab 产品需求基线 v2.1

状态：已按项目负责人本轮口述对齐产品方向；技术/部署方案另行评审。日期：2026-10-26。优先级：后续明确的口述需求覆盖原始章程中矛盾的“免登录、匿名汇总、账户延期”等条款。名称暂定。

## 1. 产品目标与非目标

目标：为教师提供可在课堂投影、全屏操作并解释规律的交互教学资源；任何人也可自行注册使用。先用一个真实实验打通从注册、浏览、交互、个人收藏/历史到后台行为分析的完整链路。首版免费，网页访问，不区分教师/学生角色。

非目标：布置作业、班级/成绩管理、收费、编辑器、批量造实验、教师/学生差异权限。线下离线包/PWA 与强制登录存在授权冲突，暂不承诺离线可用；须后续单独定义脱网身份与缓存策略。

## 2. 角色与可见信息

- 访客：可见品牌/登录注册入口；**实验目录、运行、个人数据均需登录**。可见首页宣传信息不属于实验资源。
- 普通账号：自行注册（手机号或邮箱 + 密码，首版不验证号码/邮箱归属），登录后查找并运行资源，收藏、取消收藏，查看自己的收藏及粗粒度使用历史；不查看他人数据或平台内部报告。
- 平台维护者：通过独立受保护的运维入口/工具取回按账号关联的使用事件、错误和反馈报告，分析内容受欢迎程度、常用交互、疑似卡点及版本问题；不向普通账号暴露内部诊断。首版不必做图形化管理后台，但必须有经授权的导出/查询方式。

账号标识仅用于区分站内账户，**不等于已核实真实人身份**；不验证归属意味着可能抢注他人号码/邮箱，不提供未经证明的自助找回/换绑功能。账号应有内部随机 ID，手机号/邮箱不作为资源 URL 或事件中的公开键。

## 3. 两种不同的数据产品

### A. 给本人看的“我的”
- 我的收藏：资源 ID 与收藏时间；可一键再次打开，可取消收藏。
- 最近使用：按实验/交互资源去重，只呈现打开过什么及最近打开时间（可显示次数，但首版不要求）；**不呈现每次参数拖动明细**。
- 可选的参数状态：只在用户明确点击“保存当前设置”时，保存一份该实验的当前参数快照；再次打开可选择恢复。首版先定义接口与迁移规则，是否提供按钮由纵向切片验证决定；绝不自动保存每次拖动或把数值塞进行为历史。

### B. 给平台看的内部分析
目的仅为了解用户喜欢哪些资源、通常怎么使用、哪里可能遇到困难，以便改进内容和程序。每条事件关联内部账号 ID、资源 ID、资源/程序版本和粗粒度时间；必要时有设备大类。最小事件：资源打开、首次实质交互、控件**类别**被使用（按一次会话去重或节流）、重置、全屏进出、客户端错误类别、主动反馈类别。无需每帧轨迹、键入文本、滑块连续值、原始 URL 查询串、屏幕录像。参数具体值仅在用户**主动保存设置**时作为个人数据保存，不并入分析事件。

分析时要区分“直接观察”与“推测”：打开量不代表教师人数；全屏不一定是课堂；频繁重置可能是重复演示，也可能是操作困难。后台可按资源、版本、控件类别和时间窗汇总，也可在受限权限内定位单账号问题；导出需有最小访问范围、用途与留存期限。错误/反馈不可泄露账号口令或个人输入。

## 4. 首版闭环与验收场景

1. 新账号用手机号**或**邮箱和密码注册；重复标识拒绝；登录错误密码拒绝；退出登录后不能访问实验；未登录直达资源 URL/API 被拒绝；过期会话重新登录。
2. 登录用户能按学科/学段/知识点找实验并在中英两种语言下操作。一个真实的“一次函数/二次函数参数联动”实验作为首个端到端样例：公式、范围、边界和说明可核查；手机及投影可用；重置/全屏可用。
3. 收藏后在另一会话能从“我的收藏”打开；取消收藏生效。访问两个资源后“最近使用”按资源去重；不展示参数拖动流水。
4. 同一账号的资源打开与互动类别事件能够在私有后台导出/查询；另一普通账号无法读取该账号收藏、历史、事件或错误报告。禁用/断开分析通道不妨碍核心实验与收藏历史。
5. 若实现“保存当前设置”：保存一次快照，刷新后显式恢复；实验版本变化或参数不兼容时安全退回默认值，并给出说明；没有显式保存则不持久化参数。
6. 测试涵盖口令存储、会话/授权、跨账号隔离、API 与页面行为、模型边界、移动/投影、异常与数据最小化；保留真实运行证据。没有生产部署批准，不宣称公网可用。

## 5. 取舍与待定

- 首版实现收藏和粗粒度最近使用；参数快照作为有条件的下一条功能，**不为了它延误主闭环**。
- 首款实验沿用函数图像；新增实验按教学准确性和需求评审，不以数量为目标。
- 密码找回、账号验证、留存期限、服务地域、最终开源许可与上线合规，需在公开服务前落实；**账号删除与个人数据导出经 2026-10-27 决定不列入首版范围**（见 §6，放弃的不是"没实现"，而是"这一版不提供"，因此界面与文档一律不得宣称可自助删除/导出）；本地验证时也不应提交真实个人资料或生产凭据。
- 第三方资源使用不是当前需求和架构阶段的阻塞项；首版样例采用自制内容，选用外部资源时再处理具体来源。

## 6. 决策记录（按日期，覆盖本文早前的待定项）

**2026-10-27（项目负责人决定）**

1. **首版不做账号删除、不做个人数据导出。** 两者都是"明确不在范围内"，不是待实现的缺口。相应地：应用内隐私说明、README、状态文档**不得**声称支持自助删除或导出；如需终止使用，当前真实可用的手段只有项目维护者在数据库层停用账号（无 HTTP 入口，见 `docs/ops/runbook.md`）。该决定带来的残余风险（个人对自身数据缺少自助处置入口）由负责人知晓并接受，记录在 `docs/privacy/launch-readiness.md` §2。
2. **不设"未成年人禁止使用"的年龄门槛**（本产品是教学用途，课堂里本来就有未成年人）。同时明确：**不得由此推断"无需处理儿童个人数据"**。保留一项最小必要的合规核查——真实服务地区、以及服务实际会触达哪一类个人数据——在公开上线前用事实回答，而不是臆造法定年龄、也不加硬性年龄闸门。见 `docs/privacy/launch-readiness.md` §3。
3. **其余发布前工作继续**：依赖安全（`npm audit` 的开发工具链公告）、测试路径、开源许可决策。
4. **开源许可仍未选择**：候选为 MIT 或 Apache-2.0，由负责人决定；在决定并落盘 `LICENSE` 之前，仓库**没有**许可证文件，任何人都不得据此认为已获得开源授权（`docs/third-party.md`）。
5. **GitHub Pages 只用于静态介绍页**，不支持本应用：它是强制登录的 Fastify + SQLite 同源动态应用，Pages 只能托管静态文件。**暂不启用 Pages**，因为一个不能登录的空壳会误导访问者；也不得以假后端、假数据伪装成完整应用（`docs/ops/deployment-plan.md` §2.1）。
6. **上线（部署、域名、凭证、公网可达）仍需负责人单独授权**；同意"继续推进发布前工作"不等于同意"把网站放到公网上"。
