# ADR-002 — 从需求基线推导系统结构（待实现验证）

日期：2026-10-26。依据：`docs/requirements-v2.1.md`；此文件取代已撤回的 ADR-000 技术结论，ADR-001 插件契约须按“可保存参数”重审。**本 ADR 不授权生产部署。**

## 1. 必须先解决的宏观变化

首版强制登录、跨会话收藏/历史、平台按账号分析 → 纯静态站点不能独立完成。系统必须同时有浏览器 UI、受保护 API、持久数据存储和私有运维查询。PWA 离线与强制登录冲突，单列未来专题，不把半离线体验混进首版。普通账号不分学生/教师角色，但**维护者权限必须独立于普通账号**；“不分师生”不等于“所有账号能看后台”。

## 2. 推荐边界（模块化单体，避免先拆微服务）

```
浏览器 Web（目录/实验宿主/我的收藏与最近使用）
    │ 同源 HTTPS；登录态只通过安全 Cookie
    ▼
API（注册登录/会话/资源目录/收藏/历史/事件接收/反馈）
    ├─ 身份与授权：普通账号只能看自己的数据；运维权限另设
    ├─ 内容索引：稳定资源 ID + 内容版本 + 多语言元数据
    ├─ 个人数据：收藏、去重的最近使用、可选的显式快照
    ├─ 诊断事件：白名单事件、节流、最小字段、故障隔离
    └─ 私有查询/导出：按权限读汇总和诊断，不挂在公共页面
         ▼
持久数据库（迁移、唯一约束、按账号/资源/时间索引、备份）
```

浏览器侧负责绘图/交互与科学计算；服务器不接收逐帧参数流。保留原型里可验证的实验模型、双语字典、搜索与宿主 UI，但重审其路由门禁、事件发送、状态恢复和测试，不能直接把免登录原型当完成品。UI 与 API 通过稳定资源 ID 相连，插件不得直接调用数据库、授权 API 或统计服务。

## 3. 数据模型和写入语义（概念级，不先绑数据库）

- `account(id, login_kind, normalized_login, password_hash, created_at, status)`：随机内部 ID、唯一标识；口令只存安全哈希；号码/邮箱未经归属验证必须标示 `unverified`，不误称真实身份。
- `session(id, account_id, expiry, revoked_at)`：可撤销且过期；服务端授权以会话为准。Cookie `HttpOnly`、`Secure`、`SameSite`；登录限速、CSRF 防护、密码哈希算法和审计在实现前写入安全测试。
- `favorite(account_id, experiment_id, created_at)`：唯一键防重复，删除仅影响本人。
- `recent_use(account_id, experiment_id, last_opened_at)`：按资源去重更新；与事件日志分开，避免用高频行为流水重建“我的”。
- `saved_state(account_id, experiment_id, content_version, schema_version, values, updated_at)`：只有显式保存才写；每资源至多一个当前快照；允许值须经实验 schema 白名单与大小限制。此项可延期，不能阻断主流程。
- `event(id, account_id, experiment_id, event_type, category, content_version, app_version, coarse_time)`：有限白名单、节流与限流；不存自由文本/具体滑块值。错误/反馈另有最小结构，可能带敏感文本时隔离清洗。个人历史不直接暴露 `event` 原始表。

网络失败时实验仍可运行；收藏/历史写入若失败则明确提示，不能假称已保存。事件接收失败不阻断实验，也不制造虚假成功统计；事件可丢失，后台显示数据缺口。账户/收藏/最近使用是**强一致产品功能**，事件分析是**尽力而为诊断功能**，二者不得混用。

## 4. 技术决策范围与延迟决策

- 推荐单仓库：一个 Web 应用 + 一个 API 服务 + 共享内容契约/校验；先不创建一堆空包。React/TS/Vite 原型可审后复用，服务端选 Node/TypeScript 倾向同语言共享 schema，不在未知服务器环境前锁定部署方式。
- 数据库必须有迁移和备份恢复测试；SQLite 单机与 PostgreSQL 的取舍需依服务器资源、并发、备份与运维能力实测后决定，**不能用“以后轻松切换”作保证**。本地可用临时开发数据库，但上线前要用目标数据库跑同一套迁移/授权测试。
- 账号口令不可明文/可逆存储；不能用前端 `localStorage` 伪装登录。未验证号码邮箱时避免不可信找回与伪造身份展示。
- 数据按用途分开：个人功能与诊断事件不互相依赖；设定存储上限、索引、清理和运维导出权限。公开前评估未成年人使用、告知、删除请求、实际服务地域及留存政策。
- 实验插件契约引入可选、版本化 `serializeState()/restoreState()`（若开启保存设置）和参数 schema；重置恢复教学默认值，不等同于“恢复用户保存”。首次纵向切片里先钉住一个稳定资源 ID，并加契约测试；第二个异科实验验收前复核抽象是否真通用。

## 5. 阶段门禁（先闭环，再扩张）

| 阶段 | 产物 | 退出判据 |
|---|---|---|
| R 需求基线 | 用户场景、非目标、数据用途、验收场景 | 关键冲突有明确优先级；更改须回到需求影响表 |
| A 架构与遗留审计 | 边界、数据字典、权限矩阵、部署候选、原型复用/重做表、风险 | 用匿名访问、跨账号读写、会话失效、事件断网等场景审查无结构性漏项 |
| B 一条真实纵向切片 | 注册登录→资源→交互→收藏/历史→后台事件查询 | API/模型/UI 自动化通过；真实手机尺寸及投影截图；无假登录/假数据 |
| C 工程化与内容评审 | CI、迁移/备份恢复、可访问性、科学依据、第二实验扩展验证 | 新内容无需改核心；旧实验回归；失败/回滚演练 |
| D 测试环境 | 隔离部署、HTTPS、监控、隐私文案、演示数据 | 与既有服务无冲突；用户授权部署、实际 URL 和回滚证据 |
| E 公开发布与运营 | 上线合规、管理流程、用户反馈、版本迭代 | 单独批准；只据真实数据调整优先级 |

每阶段以“可观察的退出判据”关门；新增需求先看它改变哪条不变量、数据表/API/测试/部署哪些边界，不在上一阶段遗留重大冲突时靠局部补丁进入下一阶段。技术细节由实施者自选并记录，只有影响产品、成本、公开上线或风险的决策上交。

## 6. 遗留原型处置

免登录原型已在本地形成 `apps/web`、`experiments/math-functions`、`tests/e2e` 等文件，但**尚无 git 仓库/提交，也未按新要求验证**。先冻结：不部署、不声称 M1 完成。A 阶段逐模块分类：可复用（纯模型、原创 SVG、翻译等）/需改造（目录路由、宿主事件、用户状态）/废弃（任何“无登录即访问资源”的假设）；以可复现测试决定，而非因“已经写了”就保留。
